ReviewHive Skills 系统详解

从注册、注入到执行循环——深入理解子 Agent 如何通过技能与代码工作区交互

🔍 总览

ReviewHive 的 Skills 系统是子 Agent 与代码工作区之间的桥梁。每个子 Agent（安全、性能、规范、测试、视觉）在评审过程中，通过 LLM 输出的 JSON 指令来调用技能，获取代码内容、搜索结果、知识库片段等信息，最终汇总为结构化的 findings。

核心设计理念：

  • LLM 驱动：由大模型决定何时调用哪个技能、传什么参数，而非硬编码流程
  • JSON 协议：Agent 与技能之间通过严格的 JSON 输出契约通信
  • 有限循环：每轮只能调用一个技能或输出最终结论，最多 N 轮后强制收敛
  • 上下文隔离：技能通过 SkillContext 访问工作区，不直接持有 Agent 状态

📐 技能定义

每个技能是一个 Skill 数据类实例，定义在 reviewhive/skills/registry.py：

@dataclass
class Skill:
    name: str              # 技能唯一标识，如 "read_file"
    description: str       # 自然语言描述（渲染到系统提示词）
    parameters: dict       # JSON Schema，描述参数结构
    handler: Handler       # 实际执行函数 (sync 或 async)
    tags: list[str]        # 可选标签

Handler 类型签名：

Handler = Callable[[dict[str, Any], SkillContext], Any]
# 同步 handler 返回 str
# 异步 handler 返回 Awaitable[str]

示例：read_file 技能定义

# reviewhive/skills/builtin.py → _skill_read_file()

Skill(
    name="read_file",
    description="读取工作区中某个文件的完整内容（带行号）",
    parameters={
        "type": "object",
        "properties": {
            "path": {"type": "string", "description": "文件名"}
        },
        "required": ["path"],
    },
    handler=handler,  # 闭包函数，接收 (args, ctx)
)

📋 注册表

SkillRegistry 是技能的容器，提供注册、查询、提示词渲染、执行四大能力：

方法作用调用方
register(skill)将技能加入注册表build_*_registry()
render_prompt()渲染可用技能列表为文本SubAgent._system_prompt()
execute(name, args, ctx)按名称查找并执行技能SubAgent._run_inner()
describe()返回技能元信息列表API / 调试

两种注册表构建器

定义在 reviewhive/skills/builtin.py：

def build_standard_registry() -> SkillRegistry:
    """标准评审注册表：5 个技能"""
    registry = SkillRegistry()
    for skill in (
        _skill_list_files(),    # 列出工作区文件
        _skill_read_file(),     # 读取文件内容
        _skill_grep_code(),     # 正则搜索代码
        _skill_search_kb(),     # 知识库检索
        _skill_analyze_diff(),  # 分析 diff
    ):
        registry.register(skill)
    return registry

def build_vision_registry() -> SkillRegistry:
    """视觉评审注册表：3 个技能"""
    registry = SkillRegistry()
    for skill in (
        _skill_list_files(),    # 列出工作区文件
        _skill_read_image(),    # 解读图片
        _skill_search_kb(),     # 知识库检索
    ):
        registry.register(skill)
    return registry
注册表选择逻辑（pipeline.py）

主流程 reviewhive/core/pipeline.py 根据 Agent 角色决定使用哪个注册表：

  • vision Agent → build_vision_registry()（需要 read_image）
  • 其他 Agent → build_standard_registry()（需要代码读取与搜索）

🔄 技能调用循环

核心循环在 reviewhive/agents/base.py 的 SubAgent._run_inner() 中：

system_prompt
角色 + 技能列表 + 契约
→
LLM.chat()
JSON 模式输出
→
extract_json()
解析 JSON 决策
→
分支判断
skill or final?
# reviewhive/agents/base.py → _run_inner() 简化逻辑

async def _run_inner(self, ctx, focus_points, context_chunks, emit):
    messages = [
        {"role": "system", "content": self._system_prompt()},
        {"role": "user",   "content": self._task_brief(ctx, ...)},
    ]

    for round_no in range(1, self.max_loops + 2):
        force_final = round_no > self.max_loops

        if force_final:
            messages.append({"role": "user",
                "content": "技能调用次数已达上限，请直接输出 final JSON。"})

        raw = await self.llm.chat(messages, json_mode=True)
        messages.append({"role": "assistant", "content": raw})
        decision = extract_json(raw)

        action = decision.get("action")

        if action == "final" or force_final:
            findings = _parse_findings(decision.get("findings", []))
            return AgentResult(agent=self.profile.name,
                               findings=findings,
                               notes=decision.get("notes", ""))

        if action == "skill":
            skill_name = decision["skill"]
            arguments  = decision["arguments"]
            result = await self.registry.execute(skill_name, arguments, ctx)
            messages.append({"role": "user",
                "content": f"技能 {skill_name} 的执行结果：\n{result[:6000]}"})
            continue

循环关键特性

  • 每轮一次：LLM 每轮只能调用一个技能或输出最终结论
  • 有限轮次：默认 max_loops=4，超出后强制输出 final
  • 结果截断：技能返回结果截断到 6000 字符，防止上下文膨胀
  • 错误恢复：JSON 解析失败时提示重试，未知 action 时提示纠正
  • 消息累积：每轮 LLM 输出和技能结果都追加到 messages，保持完整对话历史

💬 提示词注入

技能的描述文本通过 SkillRegistry.render_prompt() 自动注入到 Agent 的系统提示词中：

渲染流程

# reviewhive/skills/registry.py → render_prompt()

def render_prompt(self) -> str:
    lines = ["可用技能："]
    for skill in self._skills.values():
        params = ", ".join(
            f"{pname}: {pspec.get('type', 'any')}"
            for pname, pspec in skill.parameters.get("properties", {}).items()
        )
        lines.append(f"- {skill.name}({params})：{skill.description}")
    return "\n".join(lines)

渲染结果示例（标准注册表）

可用技能：
- list_files()：列出本次提交评审的所有代码文件及大小
- read_file(path: string)：读取工作区中某个文件的完整内容（带行号）
- grep_code(pattern: string, file: string)：在工作区代码中按正则搜索...
- search_kb(query: string, kind: string)：混合检索评审知识库...
- analyze_diff()：解析 unified diff...

注入位置

# reviewhive/agents/base.py → _system_prompt()

def _system_prompt(self) -> str:
    principles = "\n".join(f"- {item}" for item in self.profile.principles)
    return (
        f"你是 ReviewHive 代码评审团队中的「{self.profile.title}」...\n"
        f"使命：{self.profile.goal}\n"
        f"评审原则：\n{principles}\n\n"
        f"{self.registry.render_prompt()}\n\n"    # ← 技能列表注入此处
        f"{_OUTPUT_CONTRACT}"                       # ← JSON 输出契约
    )

📡 可观测性

每次技能执行都会被 OpenTelemetry span 追踪，定义在 reviewhive/skills/registry.py：

# reviewhive/skills/registry.py → execute()

async def execute(self, name, arguments, ctx) -> str:
    skill = self._skills.get(name)
    if skill is None:
        return f"错误：未知技能 {name}，..."

    with span(
        f"skill.{name}",           # span 名称
        KIND_TOOL,                  # span 类型 = tool
        {"arguments": json.dumps(arguments, ensure_ascii=False)[:500]}
    ):
        result = skill.handler(arguments or {}, ctx)
        if inspect.isawaitable(result):
            result = await result
        return str(result)

这些 span 会出现在 Arize Phoenix 等 OTel 兼容的追踪 UI 中，可以看到：

  • 每个 Agent 调用了哪些技能、调用顺序
  • 每次技能调用的参数和耗时
  • 技能调用在整个评审 pipeline 中的位置

🔧 扩展指南：添加自定义技能

步骤 1：定义技能

在 reviewhive/skills/builtin.py 中添加新的工厂函数：

def _skill_my_custom() -> Skill:
    async def handler(args: dict, ctx: SkillContext) -> str:
        param = str(args.get("param", ""))
        # 通过 ctx.workspace 访问代码
        # 通过 ctx.retriever 访问知识库
        # 通过 ctx.vision 访问多模态
        return f"执行结果：..."

    return Skill(
        name="my_custom",
        description="描述这个技能做什么",
        parameters={
            "type": "object",
            "properties": {
                "param": {"type": "string", "description": "参数说明"},
            },
            "required": ["param"],
        },
        handler=handler,
    )

步骤 2：注册到注册表

def build_standard_registry() -> SkillRegistry:
    registry = SkillRegistry()
    for skill in (
        _skill_list_files(),
        _skill_read_file(),
        _skill_grep_code(),
        _skill_search_kb(),
        _skill_analyze_diff(),
        _skill_my_custom(),     # ← 加入此处
    ):
        registry.register(skill)
    return registry

步骤 3：自动生效

无需修改 Agent 代码。新技能会：

  1. 自动出现在 render_prompt() 的技能列表中
  2. LLM 在系统提示词中看到新技能描述
  3. LLM 可在 JSON 输出中通过 {"action":"skill","skill":"my_custom","arguments":{...}} 调用
  4. registry.execute() 自动路由到对应 handler
  5. OTel span 自动记录执行过程
